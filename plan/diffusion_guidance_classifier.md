# Diffusion Guidance Classifier Plan

## Goal

Train a collision/risk classifier for diffusion command generation without reinforcement learning.

The classifier should predict whether a candidate velocity command sequence will collide with local obstacles. After training, it can be used as guidance during DDPM denoising, pushing generated command sequences toward lower collision risk.

The key idea is:

```text
cropped neural map + state condition -> shared encoder -> condition feature
condition feature + vel_cmd_seq -> risk classifier -> collision probability
```

The classifier is supervised by labels generated from `cost_map_crop`, not by PPO rewards.

## Dataset Extension

The current navigation diffusion dataset contains local neural map features and command targets, but it should be extended with local cost information:

```text
cost_map_crop: [N, 4, cost_crop_size, cost_crop_size]
obstacle_mask_crop: [N, 4, cost_crop_size, cost_crop_size] optional
distance_to_obstacle_crop: [N, 1, cost_crop_size, cost_crop_size] optional
cost_crop_size
cost_obstacle_threshold
velocity_command_dt
robot_radius_cells
```

For the first implementation, keep `cost_map_crop` the same size as the neural-map crop. This matches the rolling-optimization setting: each command generation step only needs to be locally reasonable in the near-field crop, and later replanning steps handle farther obstacles.

The collision label therefore means local crop collision, not full-horizon collision:

```text
local_crop_collision = 1 if the in-crop predicted path intersects an obstacle
local_crop_collision = 0 otherwise
```

Predicted path points outside the crop are cropped out and are not checked. The dataset or checker should still expose debug metadata such as:

```text
checked_step_mask
checked_path_fraction
out_of_crop_fraction
```

This keeps the label semantics explicit: a command labeled safe may only be safe for the part of the predicted path that lies inside the local crop.

The cost map should be used only to produce supervision labels and evaluation signals. It should not be required as an input to the DDPM policy, otherwise the deployed policy would depend on an explicit cost map.

## Model Structure

Use a shared condition encoder:

```text
map_crop
uncertainty_crop
goal_delta
current_latent
current_heading
        |
 shared CNN/vector encoder
        |
 condition feature c
```

Then split into two heads:

```text
DDPM denoiser:
  input: noisy command x_t, timestep t, condition feature c
  output: predicted noise

Risk classifier:
  input: candidate command sequence x, condition feature c
  output: collision logit
```

The classifier must receive the candidate `vel_cmd_seq`. If it only receives the condition feature, it can only learn whether the local scene is generally risky, not whether a specific command sequence is risky.

## Collision Label Generation

For each candidate command sequence:

1. Convert training target back to command form if needed:

```text
[vx, vy, sin_heading, cos_heading] -> [vx, vy, heading]
```

2. Integrate the command sequence into a predicted local/world path.

3. Crop out path points outside `cost_map_crop`.

4. Compare the in-crop predicted path with `cost_map_crop`.

5. Assign label:

```text
label = 1 if predicted path intersects an impassable obstacle
label = 0 otherwise
```

The collision checker should consider:

- command `dt`
- local-frame to world-frame velocity rotation
- current or predicted heading
- robot footprint / safety radius
- obstacle threshold
- interpolation between command steps
- out-of-crop behavior
- checked path fraction

The label should always come from the checker. The source of the command sequence should not directly determine whether it is safe or risky.

For the first implementation, if `cost_map_crop` has 4 directional channels, use a conservative obstacle cost:

```text
obstacle_cost = max(cost_map_crop over directional channels)
```

Then mark collision when any robot-footprint cell along the interpolated in-crop path exceeds `cost_obstacle_threshold`.

## Classifier Training Data

Candidate command sequences should come from three sources.

### Dataset Commands

Use the original `velocity_commands` from the dataset.

These are usually safe because they come from A* and the position controller, but they should still be checked against `cost_map_crop`.

### DDPM Sampled Commands

Use a pretrained or currently trained DDPM to sample multiple command sequences for the same condition.

This source is important because the classifier will guide DDPM outputs at inference time, so it should see DDPM-like samples during training.

The sampled commands may be safe or risky. Labels are generated by the collision checker.

### Perturbed Dataset Commands

Create harder examples by perturbing dataset commands:

```text
velocity noise
heading noise
lateral offset
speed scaling
command truncation
reverse or sideways bias
```

These examples are useful when DDPM samples do not provide enough near-boundary or risky cases.

For joint training, build candidate commands online for each batch. A starting per-condition composition is:

```text
K = 10 candidates
1 candidate from the original dataset command
4 candidates from DDPM clean predictions during sampling
5 candidates from perturbed dataset commands
```

The DDPM candidates should be clean-sequence estimates, not noisy `x_t` states. During a 16-step sampling run, save `x0_pred` at selected sampling iterations:

```text
candidate_steps = 4, 8, 12, 16
```

These are sampling iteration indices, not raw diffusion timesteps. At each selected iteration, the sampler has a current noisy state `x_t` at diffusion timestep `t`; the denoiser predicts noise, and the algorithm estimates:

```text
x0_pred = estimate_clean_sequence(x_t, t, predicted_noise)
```

The classifier receives `x0_pred`. It does not receive `t` in the first implementation.

This ratio should be adjusted based on the safe/risky class balance. Track class balance by source:

```text
dataset collision ratio
DDPM collision ratio
perturbation collision ratio
overall positive ratio
```

## Training Objective

Train with supervised learning:

```text
loss = loss_ddpm + lambda_risk * loss_risk
```

Where:

```text
loss_ddpm = masked MSE(pred_noise, noise)
loss_risk = BCEWithLogitsLoss(risk_logit, collision_label)
```

Gradient ownership in the first joint implementation should be:

```text
loss_ddpm -> shared encoder + DDPM denoiser
loss_risk -> shared encoder + risk classifier
loss_risk should not update the DDPM denoiser
DDPM sampled candidates should be detached before classifier training
```

If labels are imbalanced, use positive weighting, balanced sampling, or hard-negative mining.

Soft targets can also be added later:

```text
soft_risk = exp(-min_obstacle_distance / sigma)
```

This may produce smoother gradients than binary collision labels.

## Joint Training Schedule

The first implementation should use joint training with an EMA target DDPM for candidate generation.

### Online DDPM

The online model is optimized by the training losses:

```text
online shared encoder:
  updated by loss_ddpm + lambda_risk * loss_risk

online DDPM denoiser:
  updated by loss_ddpm only

online risk classifier:
  updated by loss_risk only
```

### EMA Target DDPM

Maintain a delayed target DDPM, similar to a target network in DQN-style training:

```text
target shared encoder
target DDPM denoiser
```

The target DDPM is used only to generate online DDPM candidate commands. It does not receive gradients.

Update the target DDPM with fixed-tau EMA after each optimizer step:

```text
theta_target = tau * theta_online + (1 - tau) * theta_target
tau = 0.005 initially
```

### Per-Batch Training Flow

For each training batch:

```text
1. Use online encoder + online denoiser to compute normal DDPM denoise loss.
2. Use target encoder + target denoiser to run DDPM sampling for the same conditions.
3. Save x0_pred at sampling iterations 4, 8, 12, and 16.
4. Build candidate commands:
   - 1 original dataset command
   - 4 target-DDPM x0_pred commands
   - 5 perturbed dataset commands
5. Use the collision checker and cost_map_crop to create local_crop_collision labels.
6. Use online encoder + risk classifier to compute risk loss on all candidates.
7. Optimize:
   loss = loss_ddpm + lambda_risk * loss_risk
8. EMA-update the target DDPM.
```

### Lambda Schedule

Use a scheduled `lambda_risk`, starting small and reaching its peak near a preset global step such as 30k.

A recommended cosine schedule is:

```text
if global_step < risk_start_step:
    lambda_risk = 0
else:
    progress = min((global_step - risk_start_step) / risk_warmup_steps, 1)
    lambda_risk = lambda_risk_max * 0.5 * (1 - cos(pi * progress))
```

Initial values:

```text
risk_start_step = 3000
risk_warmup_steps = 30000
lambda_risk_max = 0.1
ema_tau = 0.005
```

Recommended learning-rate relationship:

```text
encoder_lr < denoiser_lr
encoder_lr < classifier_lr
```

The risk loss should improve condition features without overwhelming the DDPM generation objective.

The first implementation should sample DDPM candidates every batch for correctness and simplicity. If this becomes too slow, add a batch-aligned candidate cache later.

## Offline Validation Flow

Even with joint training as the main path, keep an offline validation flow for debugging.

The offline flow should validate:

```text
1. cost_map_crop + collision checker labels are plausible
2. the classifier is sensitive to candidate command changes under the same condition
3. classifier scores can separate safe and risky candidate commands
```

Recommended offline stages:

```text
1. Save candidate commands from dataset, target-DDPM sampling, and perturbations.
2. Label each candidate with the same collision checker used in training.
3. Train or evaluate a standalone classifier with the DDPM encoder frozen.
4. For the same condition, compare classifier scores across many different commands.
5. Compare classifier scores with checker labels, min/max path cost, and checked_path_fraction.
```

This flow helps diagnose whether failures come from the checker, the classifier, the shared encoder, DDPM sample quality, or guidance scale.

## Guidance During DDPM Sampling

After training, use the classifier to guide the denoising process.

Basic clean-sequence guidance:

```text
1. At denoising step t, estimate x0_pred from x_t.
2. Compute risk_logit = classifier(x0_pred, condition_feature).
3. Compute grad = d risk_logit / d x_t.
4. Update x_t in the direction that reduces risk.
```

Conceptually:

```text
x_t <- x_t - guidance_scale * grad_x collision_risk
```

A more advanced version is timestep-aware classifier guidance:

```text
classifier(x_t, t, condition_feature) -> collision_logit
```

This matches the noisy states seen during DDPM denoising, but it requires training the classifier with noised command sequences:

```text
x_t = q_sample(x0, t)
classifier(x_t, t, c) -> collision label
```

The first implementation should use clean-sequence guidance because it is simpler.

## Main Risks

1. The classifier may ignore the command sequence and only learn scene risk.
   Mitigation: include diverse commands for the same condition and verify command sensitivity.

2. The classifier may see too few risky samples.
   Mitigation: oversample DDPM failures, add perturbations, and rebalance the BCE loss.

3. The local cost crop only labels near-field safety.
   Mitigation: crop out out-of-range path points, log `checked_path_fraction`, and evaluate high `out_of_crop_fraction` samples separately.

4. Binary collision labels may produce sparse gradients.
   Mitigation: add distance-to-obstacle or soft risk targets.

5. Shared encoder training may hurt DDPM command quality.
   Mitigation: small encoder learning rate, scheduled `lambda_risk`, fixed-tau EMA target DDPM, and clear gradient ownership.

## First Implementation Target

The first practical milestone should be:

```text
1. Extend augmented dataset with cost_map_crop metadata and tensors.
2. Implement command-sequence collision checker with local-crop label semantics.
3. Add risk classifier head that consumes condition feature and candidate command sequence.
4. Add EMA target DDPM for per-batch online candidate generation.
5. Implement joint training:
   - DDPM denoise loss
   - risk BCE loss
   - scheduled lambda_risk
   - fixed EMA tau
   - detached DDPM candidates
6. Track source-wise collision ratios, classifier metrics, and DDPM command metrics.
7. Add offline validation scripts for checker/classifier diagnostics.
8. Add simple clean-sequence classifier guidance to DDPM sampling.
9. Compare unguided vs guided DDPM on local collision rate and goal progress.
```

This avoids PPO initially and keeps the pipeline easier to debug.
